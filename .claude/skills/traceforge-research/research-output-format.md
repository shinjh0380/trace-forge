# Research Output Format

`traceforge-research` 스킬의 결과물 작성 형식.
모든 리서치 보고서는 이 구조를 따릅니다.

---

## 보고서 구조

```markdown
# Research Report: [조사 주제]

날짜: YYYY-MM-DD
요청자: [세션 컨텍스트]

---

## Question

[해결하려는 설계 질문을 명확하게 1-3문장으로]

예시:
"TraceForge의 sink 목록을 스레드 안전하게 관리하는 최적 방법은 무엇인가?
lock을 사용하는 경우 Log hot path에 영향을 주지 않으면서 sink 추가/제거를
지원해야 한다."

---

## Context

[왜 이 질문이 필요한지, 현재 TraceForge 상태와의 연결]

- 현재 상황: ...
- 제약 조건: ...
- Unity 6.3 관련 제약: ...

---

## Findings

[수집한 사실, 패턴, Unity API 동작, 기존 사례 등]

|------------|--------|----------------------|
| ...        | ...    | ...                   |

---

```

---

## 작성 원칙

1. **Findings는 사실만** — 의견이나 권장은 Recommendation에
2. **Options는 실제로 고려 가능한 것만** — 이론적 옵션 X
3. **코드 예시는 최소화** — 개념을 보여주는 수준으로
4. **Impact는 구체적으로** — "성능에 영향줄 수 있음" X → "Log hot path에서 lock 추가로 X ns 오버헤드 예상" O
5. **스킬 체크리스트 영향 명시** — 설계가 바뀌면 관련 체크리스트도 업데이트 필요
